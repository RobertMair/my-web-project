# Introduction

The purpose of the website is to transform the existing [Canberra Modern](https://canberramodern.com) (CM) website (stated as ‘awful’ by their own admission) into an ‘engaging and visually appealing’ website for people with an interest in mid-century modern architecture and design.

The redesigned website ([GitHub Repository](https://github.com/RobertMair/my-web-project/) and [Website](https://robertmair.github.io/my-web-project/index.html)) uses ‘user-centered design’ (UCD) principles and techniques to provide a modern, easy to navigate, high quality website that is visually appealing, easy to navigate, and uses technically and historically accurate content.

The aim of this reflection is to identify insight into the development process and recognise things I did well or could have done better.

# What I Learned

While I have built a few websites and completed other design and technology subjects at TAFE and UC, via this Front-end Web Design (11056) project I have improved my knowledge of HTML, CSS and JavaScript (with much reliance on W3schools (W3schools, n.d.)) and responsive design principles and CSS such as Flexbox and Grid.

The subjects course materials also greatly assisted in teaching how to plan the project using the web design workflow spread of: Discovery and research; Planning; Design; Development; Testing; and Launch spread across the three assignments.

Information architecture (IA) was another learning, and while I completed an IA review of the existing CM website to improve content categorisation and navigation, based on constructive feedback and useability principles in Steve Krug’s Don’t Make Me Think (IxDF, n.d.) and Don Normans ‘affordances and usability principals’ (Batterbee, 2020) I later changed the navigation by:

- Splitting the primary navigation into primary (key content pages) and secondary (reference/administration pages).
- Removing drop down choices from the navigation.
- Adding active page indicators (underline current page).

# Challenges and Problem Solving

The first problem was a project brief i.e., what problem is the redesign solving? Using ‘design thinking’ (Friss Dam, n.d.), the problem statement I created was ‘mid-century modern architecture and design enthusiasts and industry professionals need an easy-to-use website for research, knowledge sharing, and events.’ I then designed the new site with Nielsen-Molich Heuristics Testing (IxDF, n.d.) in mind, so rather than fixing issues in development, I would solve at design.

While this helped, learning Figma to convert low fidelity prototypes into high fidelity prototypes was time consuming but rewarding (I have now adopted Figma into my work toolchain). Additionally, HTML, CSS and JavaScript implementation was time consuming. Firstly, integrating Figma with Visual Studio Code, and then refreshing coding skills while working through responsive layout challenges.

Even simple items e.g., fitting and center aligning images horizontally and vertically, could take research and troubleshooting for HTML and CSS implementation.

Eventually, I was able to overcome coding issues with online research and W3schools excellent website to faithfully replicate the Figma derived high fidelity prototype in code.

# Evaluation of My Website

I believe the website redesign is effective, and close to ‘pixel perfect’ with the Figma design as I used pixel dimensions of Figma elements. While this made CSS easier to create, I learned the use of PX (pixels) in responsive web design and changing element size, such as fonts, with @media queries, may not be ‘best practice’, rather using EM or REM can be more dynamic and fluid (Ochuko, 2022).

However, I feel the user experience (UX) is OK and design represents my low fidelity prototypes, such as primary navigation collapsing to a 'hamburger menu' on small screens, and use of hero image and text and content cards as outlined in the low fidelity prototypes (see [Page 1](https://github.com/RobertMair/my-web-project/tree/main/assets/images/cm-low-fidelity-prototype-1.jpg) and [Page 2](https://github.com/RobertMair/my-web-project/tree/main/assets/images/cm-low-fidelity-prototype-2.jpg))

In summary, I feel navigation is easy, contrast for accessibility mostly ok, and content is logically grouped. Regarding navigation, based on feedback, I added a ‘top of page’ button with JavaScript late in the development as some pages are long on small screens. Further, sub-pages from Architecture primary navigation don’t provide any ‘breadcrumb’ but just maintain the active page indicator as <u>Architecture</u> – something to correct.

# Future Development

Based on this project, I would like to improve my knowledge of Flexbox and Grid, and working with images, not just on-screen manipulation, but also image file optimisation (format, different files for different screen sizes).

Regarding images, the original website had little ‘branding’, just a logo based on the Canberra Olympic Pool diving board (Canberra Olympic Pool, n.d.). To improve brand identity, I abstracted the diving board into a modern flat design retaining only key details. The updated logo is also used for the new website’s ‘favicon’.

Overall, I enjoyed the creative process and increasing knowledge of the design and technical aspects of developing websites and would like to do more in the future.
